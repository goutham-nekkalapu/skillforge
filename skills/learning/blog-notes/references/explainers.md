# HTML explainers

The note is markdown. An explainer is a small single-concept HTML page next to it, for the one thing a static picture can't show well. It is not a second copy of the note.

## When one earns its place

Make an explainer only when the concept **moves** or needs **interaction**:

- several steps where state changes: a request travelling through a cache, a token stream being matched against a cached prefix, an algorithm rebalancing a ring, a consensus round;
- a before/after the reader should flip between: a prompt layout that misses the cache vs. one that hits.

Not when a static picture does the job. A flow of three boxes, a layer stack or a comparison table goes inline in the markdown (see `../yt-notes/references/visuals.md`). Most notes have **no** explainer; at most `max_explainers` (default 2). If you're unsure, it doesn't qualify.

## Build it

1. Copy `../yt-notes/assets/note-template.html` to `<explainer_prefix><Concept>.html` (from `prepare`; `<Concept>` in Title_Case with underscores, e.g. `Prompt_Caching__Cache_Lookup.html`).
2. Header: kicker `<Topic> · <site>`, the concept as the title, a one-sentence lede, and meta pills for the post (no video fields).
3. **One tab, one panel.** Keep the tab bar with a single tab (`<a class="tab" href="#explain">…</a>` ↔ `<section class="panel" id="explain">`). Put the stepper or compare component in it, with a sentence of context above and the takeaway below.
4. Build the illustration from the template's components: **stepper** for steps (`data-show`, `data-hl`, `data-move`, `data-dim`), **compare** for before/after, **graph** or **flow** for the scene. Component markup is in `../yt-notes/references/html-notes.md`. Don't hand-draw SVG.
5. Delete every other panel and every `data-example` block. Set the footer to `Generated by blog-notes · <today>`, and point the floating home button at `#explain`.
6. Check: `python3 ../yt-notes/scripts/check_note.py <file> --explainer` until `RESULT: OK`.

The page must work inside Obsidian's HTML Viewer: no inline `onclick` handlers, no external scripts or fonts, no links that leave the page (rules in `html-notes.md`).

## Place it in the note

Right where the concept is explained in the markdown, not in a separate section:

````markdown
### The exact-prefix rule

Short explanation…

```html-embed
file: <embed_dir>/Prompt_Caching__Cache_Lookup.html
```
[[Prompt_Caching__Cache_Lookup.html|▶ Step through the cache lookup]]
````

Include the `html-embed` block only when `prepare` returned an `embed_dir`. It shows the page inline with Obsidian's **HTML Embed** plugin. Always include the wikilink, which opens the page with the HTML Viewer plugin. Also add the file name to the note's `explainers:` frontmatter list. The checker fails if a linked explainer file doesn't exist.

Keep the markdown readable without the explainer: the text around it should still state the steps in a sentence or a short numbered list, so the note works on a phone or without plugins.
