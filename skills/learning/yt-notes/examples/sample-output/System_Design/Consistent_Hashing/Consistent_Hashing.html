Consistent hashing

How to spread keys across servers so that adding or removing a server moves only a small share of them, instead of reshuffling almost everything.

TL;DR

  • With hash(key) mod N, changing the number of servers moves almost every key: ~80% going from 4 to 5.
  • Consistent hashing puts servers and keys on a ring; a key belongs to the first server clockwise.
  • Adding or removing a server moves only one arc's keys: about 1/N.
  • Virtual nodes (100–200 positions per server) keep the load even.

The big picture

In a cache cluster, a sudden reshuffle of keys means a flood of cache misses hitting the database. Consistent hashing removes the link between where a key lives and how many servers exist.

Key insight

Place keys by where they sit on the ring, not by how many servers there are. Then a change only affects the neighbourhood where it happens.

Key ideas

Why hash mod N breaks

Changing N from 4 to 5 gives a different answer for most keys. A key keeps its server only when h mod 4 == h mod 5.

Added context (not from the video)

Why 80%: among any 20 consecutive hash values, h mod 4 == h mod 5 holds for just 4 of them, so about 20% stay.

The hash ring

Bend the hash range (0 to 2³²) into a circle. Hash each server's name to place it, hash each key the same way, and give each key to the first server clockwise.

Adding or removing a server

When server E joins between B and C, only the keys between B and E change owner. Removing a server is the mirror image: its keys go to the next server clockwise.

Virtual nodes

With few servers, positions land unevenly and one server can own a huge arc. Hashing each server many times (typically 100–200) spreads it into many small arcs, so load evens out, a leaving server's keys spread over many neighbours, and bigger machines can simply get more virtual nodes.

Walkthrough: server E joins

Step through what happens to ten keys when a fifth server joins.

  1. 1 · Four servers Each key takes the colour of the first server clockwise from it.
  2. 2 · A lookup This key walks clockwise and meets C first, so C owns it.
  3. 3 · E joins E hashes to a point between B and C. Keys elsewhere still meet the same server first.
  4. 4 · Only two keys move Keys between B and E now meet E before C (circled). 2 of 10 keys moved: about 1/N.
  5. 5 · Compared with mod N The same change with hash mod N would have moved about 8 of the 10 keys.

Takeaways

  1. Placement should depend on position on the ring, not on the number of servers.
  2. "Next server clockwise" is the whole lookup rule.
  3. A membership change costs about 1/N of keys, compared with almost all for mod N.
  4. Virtual nodes give balance, gentle failure and weighting.
  5. Pitfall: a ring without virtual nodes isn't balanced, and removing a server dumps all its keys on one neighbour.
